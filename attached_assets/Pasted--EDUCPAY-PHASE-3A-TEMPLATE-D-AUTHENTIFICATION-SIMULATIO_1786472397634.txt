# EDUCPAY — PHASE 3A

# TEMPLATE D’AUTHENTIFICATION + SIMULATION LOCALE

## 0. CONTEXTE DU PROJET

Tu travailles sur **EducPAY**, un SaaS professionnel destiné à la gestion de la scolarité des établissements scolaires.

L'architecture du projet doit être construite progressivement, proprement et sans anticiper les phases futures.

### Phases déjà réalisées

**Phase 1 — Fondation + Landing Page**

* architecture initiale ;
* Design System ;
* composants UI ;
* Landing Page ;
* responsive ;
* routes publiques ;
* déploiement Vercel.

**Phase 2 — Dashboard Super Admin**

* Dashboard Super Admin ;
* layout applicatif ;
* Sidebar ;
* Navbar ;
* navigation du Super Admin ;
* structure de son espace.

Ces deux phases sont considérées comme la base actuelle du projet.

# 1. MISSION DE CETTE PHASE

Nous commençons maintenant :

> **PHASE 3A — TEMPLATE D’AUTHENTIFICATION + SIMULATION LOCALE**

Cette phase est extrêmement importante.

L'authentification constitue la **porte d'entrée d'EducPAY**.

Nous devons donc construire cette partie avec une qualité professionnelle :

# 17. COMPORTEMENT DE LA SIMULATION

La simulation doit permettre de tester :

### Login réussi

Avec des identifiants de démonstration clairement définis.

Exemple conceptuel :

```text
Email : superadmin@demo.local
Mot de passe : valeur de démonstration
```

Utilise des données de démonstration qui ne correspondent à aucun vrai secret.

### Login incorrect

Afficher un message d'erreur utilisateur clair.

### Loading

Simuler un traitement asynchrone.

### Session simulée

Après connexion :

```text
Login
 ↓
Mock Auth
 ↓
Session locale
 ↓
Dashboard Super Admin
```

### Logout

```text
Dashboard
 ↓
Logout
 ↓
Suppression session simulée
 ↓
Login
```
