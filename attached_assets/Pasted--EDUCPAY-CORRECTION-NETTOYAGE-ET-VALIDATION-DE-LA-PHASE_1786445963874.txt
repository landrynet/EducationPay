# EDUCPAY — CORRECTION, NETTOYAGE ET VALIDATION DE LA PHASE 1

## Mission

Tu es responsable du développement Full-Stack du projet **EducPAY**.

Le projet a été développé trop rapidement avec plusieurs phases implémentées en avance.

Nous avons pris la décision de **revenir volontairement à une base propre**.

### État souhaité

Le projet final de cette intervention doit contenir **UNIQUEMENT LA PHASE 1**.

La Phase 1 est déjà fonctionnelle et doit être **conservée**, notamment la Landing Page et tout ce qui est nécessaire à son fonctionnement.

Les anciennes implémentations des :

* Phase 2 ;
* Phase 3 ;
* Phase 4 ;

doivent être supprimées proprement.

# 9. ARCHITECTURE PROPRE

Le projet doit avoir une architecture professionnelle et compréhensible.

Privilégier une structure claire adaptée au framework réellement utilisé.

Exemple possible :

```text
src/
├── app/
├── components/
│   ├── ui/
│   └── landing/
├── lib/
├── config/
├── types/
├── hooks/
└── styles/

public/
```

Ne copie pas obligatoirement cette structure si l'architecture actuelle est différente mais déjà propre.

Le principe est :

```text
UI
≠
logique métier
≠
configuration
≠
services
≠
types
```

# 16. DÉPENDANCES — RÈGLE PERMANENTE

### INTERDICTION STRICTE

Ne jamais utiliser une bibliothèque :

* abandonnée ;
* défectueuse ;
* instable ;
* incompatible ;
* présentant une vulnérabilité critique connue sans alternative justifiée ;
* inutilement complexe ;

Avant d'ajouter une nouvelle dépendance :

1. vérifier sa maintenance ;
2. vérifier sa compatibilité ;
3. vérifier les problèmes connus ;
4. vérifier les conflits avec le projet ;
5. vérifier si une solution native existe ;
6. vérifier si une dépendance déjà installée suffit.

### Principe

> **Moins de dépendances, mais de meilleures dépendances.**

Ne jamais ajouter une bibliothèque uniquement parce qu'un tutoriel ou un autre projet l'utilise.
